PlacidWay Social Autopilot

A production-minded n8n workflow that turns public PlacidWay content into one on-brand, fact-checked Facebook post per day, with two layers of guardrails, a human review dashboard, and alerting so nothing fails silently.

Requirements → implementation

BriefHow it's doneStatus
1 TriggerDaily 07:00 schedule, manual run, and a dashboard “Run now”✓ live
2 ExtractPublic sitemaps (robots.txt-advertised, ≤ 1 req/s, 5 requests a day), then the page's own JSON-LD with OpenGraph/HTML fallback. Captures title, URL, body, image, listed price✓ live
3 SelectWeekday content rotation + category cool-down. UNIQUE(source_url) in Postgres guarantees a URL is never posted twice✓ live
4 GenerateClaude returns structured parts (hook, 2–4 lines, CTA, 3–5 hashtags) plus a verbatim source quote per line. Code assembles the post (< 500 chars before the link)✓ live
5 Guardrails9 deterministic rules (no medical claims, every number and price must be in the source, quotes must exist on the page…) + an independent Claude reviewer. Failures are rewritten with feedback; after 3 tries they go to a human and never auto-publish✓ live
6 PublishPhoto uploaded unpublished, then a feed post with the image (immediate or natively scheduled)✓ live post
7 Review optionpublish_mode = approval | auto, switchable in the dashboard. Human edits are re-checked against the rules (server returns 422)✓ live
8 Logging & errorsEvery run logs the item, post text, FB post ID and status. Retries + an error workflow raise dashboard alerts with a specific fix✓ tested

Stretch goals covered: variety rules · branded images (smart crop + brand bar, or a rendered card when there's no image) · review dashboard · engagement read-back · Instagram cross-post path (built; needs an IG Business account to verify).

How it works

The daily pipeline

Schedule / manual→Sitemaps→Pick 1 fresh URL→Claim (UNIQUE)→JSON-LD extract→Claude writes→Rules + Claude review→Brand image→Approve / auto→Facebook

The main n8n workflow after a real run (all green): select · extract · generate + guardrails · image · save and publish.

Verified against the real system

  • End-to-end publish to the test Facebook Page, with image and permalink
  • Guardrails caught real issues (a number not in the source, an unsupported claim); both were rewritten and passed
  • Failures tested live: PlacidWay unreachable, LLM down, invalid Facebook token. Each raised an alert; failed URLs are released for retry
  • Dry-run mode records the exact Graph API calls before anything goes live

Key design decisions

  • The database, not workflow logic, enforces "never twice"
  • Structured output + code assembly, so the format is guaranteed and every claim is checkable
  • Fail closed: if the reviewer is unavailable, the draft goes to a human
  • Code-node logic lives in real, unit-tested files; a build step generates the workflows
